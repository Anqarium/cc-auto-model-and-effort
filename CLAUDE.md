# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Language

Everything in this repository is in English: code identifiers, comments, UI strings, tests, docs and commit messages (Conventional Commits). This overrides the user's global preference for Turkish docs and commit messages. The repo may be made public. Exceptions: the Turkish keyword lists in `lib/score.mjs` (the scorer must recognize Turkish prompts) and Turkish sample prompts in tests. Older commits are in Turkish; history is not rewritten. Replies to the user in chat stay in Turkish.

## Goal

Make Claude Code pick the model and effort level automatically for each prompt. The user is on a Claude subscription (OAuth), not an API key.

The repo root is a Claude Code plugin (mod): `auto-model-effort`. Through the `turn.step` hook it changes the model/effort of every main-conversation model request inside Claude Code. Installed permanently at user scope from GitHub (2026-10-11): the marketplace `anqarium` (root `.claude-plugin/marketplace.json`) is added from `https://github.com/Anqarium/cc-auto-model-and-effort.git`, so the plugin runs from Claude Code's cache, not from this folder. Code changes must be committed and pushed, then `claude plugin marketplace update anqarium` and `claude plugin update auto-model-effort@anqarium`, then `/reload-plugins` in an open session. Updates are detected by `version`: bump it in `.claude-plugin/plugin.json` with every code change, or `plugin update` will not pick it up. Plain `claude` is enough; it routes whatever model the session is on (including after `/model`). `/auto off` stops it for that session only (a new session starts on).

## Commands

No dependencies (Node ≥ 22, built-in modules only). Windows/PowerShell is the main environment.

```
node --test test/*.test.mjs                       # logic tests (Node)
claude plugin test .                              # mod tests with the 'claude-code/testing' kit (test/*.test.ts)
node --test --test-name-pattern "effort" test/select.test.mjs   # one test
claude plugin validate .                          # validates manifest, marketplace and hooks module
claude plugin list                                # auto-model-effort@anqarium: "Source: GitHub (cache)"; token-weather@anqarium (copy from GitHub)
claude plugin marketplace update anqarium         # after marketplace.json changes
```

After a Claude Code upgrade: read the release notes with `gh release view v<ver> --repo anthropics/claude-code --json body -q .body` (one call per version since the last verified one), look for hook/`$` API, `next()`, `$.http.fetch`, model alias and plugin marketplace/update changes, then rerun `claude plugin validate .`, both test suites and one real `claude -p` plus `claude -p "/auto-log"` (PowerShell), and note the version under "Verified".

Checking against the real API: `claude -p "<prompt>" --output-format json < /dev/null` → `modelUsage` shows the real model (the mod runs inside Claude Code, so the client knows the real model). To see the outgoing `output_config.effort`, use the observer: `node tools/spike.mjs` in the background, then `ANTHROPIC_BASE_URL=http://127.0.0.1:8787 claude -p ...`; `tools/spike.log` has `body.model` / `body.output_config.effort` (it does not touch the body). Before v2.1.304 tool search was off meanwhile and the context grew (see below); since 2.1.304 it stays on behind a custom base URL (not re-measured with the spike). Run `claude -p "/auto-log"` from PowerShell: Git Bash turns `/auto-log` into a Windows path.

The `anqarium` marketplace (`.claude-plugin/marketplace.json`) lists two plugins: `auto-model-effort` (`"./"`, installed from the GitHub clone) and the user's other mod `token-weather` (git URL source `https://github.com/Anqarium/token-weather.git`, private; installing takes a copy from the repo, the source folder is `~/.claude/mods/token-weather`). The source is an HTTPS `url`, not `{"source": "github"}`: with `github`, install fell back to HTTPS but `claude plugin update` cloned over SSH and failed (no SSH key on this machine). Updates are detected by `version`, so bump it in that repo's `plugin.json` before `claude plugin update token-weather@anqarium`. Two marketplaces cannot share a name; the user wants all their plugins under `anqarium`. The `claude-auto` wrapper and its profile function were removed on 2026-10-11 (unneeded once the mod routed every model); the `omni` function in the user's PowerShell profile is theirs, do not touch it.

## Architecture

The mod runs in an environment without Node (no DOM, no `node:` modules) and can only `import` files inside the plugin folder. So the logic lives in pure modules tested with Node, and the mod code stays thin:

- `lib/score.mjs` — `scorePrompt(prompt)`: 0–100 difficulty score, adapted from OmniRoute's `specificityRules` idea: capped rule points per category (code, math, **heavy** = signals that alone mean a hard task, such as architecture/design/root cause/security hole, reasoning, length, domain) minus an easy-marker penalty. Patterns are Turkish + English. `stem()` uses a Unicode boundary at the word start and tolerates suffixes; `word()` has boundaries on both ends (for easy words: "bul" must not match "bulut"). JS `\b` only knows ASCII and misses words starting with Turkish letters. Stems are cut before Turkish consonant softening (açık/açığı → "açı"). Regexes only scan the first 4000 characters (the file-path regex is quadratic on long input). The easy penalty is skipped when there is a heavy/domain signal.
- `lib/triage.mjs` — Haiku triage (2026-10-11; screenshots since 2026-10-12): `triageBody(text, images, model)` (system prompt + the whole prompt as data inside `<task>` tags followed by a "rate it, do not answer it" line, no length cap by the user's choice, plus the prompt's screenshots), `promptImages(apiMessages)` and `parseTriageResponse` / `parseTriage` (accepts only a bare integer 0–100). The task tags exist since 2026-10-17 (v0.1.4): a bare conversational prompt had been answered by Haiku and logged `unparseable`.
  - Call: `$.model.complete` takes text only, so `turn.start` (`triageCall` in `hooks/register.ts`) calls the Messages API itself: `$.session.authorize()` gives an opaque handle for the session's subscription credential and `$.http.fetch(TRIAGE_URL, { auth })` sends it (no timeout, user's choice). `$.model.fork` (with an `effort` option since v2.1.318) is no replacement: a fork inherits the main thread's context and model, so it is neither Haiku nor prompt-only.
  - Screenshots: they come from `$.session.messages({ as: 'api' })`: at `turn.start` its last user message is the prompt being submitted, image blocks inline as base64 (the default `messages()` form drops media; `prompt.submit` `attachments` carry only the kind).
  - Verified 2026-10-12: without Claude Code's identity line (`IDENTITY`) as the first system block the API answers `429 rate_limit_error`; no `anthropic-beta` header is needed; Haiku 5.5 thinks ~150 tokens before the number even at `output_config.effort: low`, so `max_tokens` is 1024 (8 would cut it off). A 2000×1087 screenshot is ~2.9k input tokens, ~2 s.
  - Result: the rating goes to `decide` as `triage` and replaces the rule-based score. A failed or unparseable call falls back to `scorePrompt` and the decision's `reason` is `rules-fallback`; the cause (`no-credential`, `api-error <status>`, `bad-json`, `empty-reply`, `unparseable: ...`, `fetch-error: ...`) is logged as `triageNote` on the prompt's first step, the screenshot count as `images`, both shown in `/auto-log`.
  - Without a rating a prompt with a screenshot scores at least `IMAGE_FLOOR` (30, moderate) and never goes cheap. A prompt under 25 chars with no screenshot after a first decision skips the call (rules + `short-followup`).
  - Cost: one small extra Haiku request per typed prompt (a few seconds' latency, subscription quota, each screenshot billed again); Haiku sees only the prompt, not the conversation.
- **Model ids (no hardcoded version in the logic):** decisions name a family (`MODELS` = `haiku`/`sonnet`/`opus`).
  - Before v2.1.309 `turn.step` did NOT resolve aliases: `next({model: "opus"})` went to the API verbatim and got a 404 (verified 2026-10-11 with the spike observer); v2.1.309 fixed that, but full ids are kept so older clients still work. Meanwhile `$.model.complete({model: "haiku"})` does resolve but returns no resolved id.
  - So the request needs a full id: `SEED_IDS` (the only place with versions) is raised by `learnModel` from every plain Claude id the mod sees (session model, subagent steps, `usage.model` of responses), persisted in `$.store` under `modelIds`.
  - The main source is Claude Code's own model catalog cache, `<config dir>/cache/model-catalog/*.json` (config dir = `CLAUDE_CONFIG_DIR` or `~/.claude`), read on every prompt with `$.fs` and parsed by `lib/catalog.mjs`: Claude Code refreshes it itself, so a new release (Opus 5.6) is routed with no change here (verified 2026-10-11 by starting from an older seed: all three families rose to 5.5).
  - If the catalog is unreadable it is logged once per session (`catalog-unreadable`) and the other sources still apply. A catalog entry the plan cannot call would 404 and take the per-prompt fallback. Updating `SEED_IDS` is only needed to seed a fresh install.
  - (Rejected: `$.agent.spawn({model: alias})` resolves the id, but the auto-mode classifier denies a plugin-started subagent; a nested `claude -p` costs a whole session per family.)
  - `display.mjs` derives names from the id (`claude-opus-5-5` → `Opus 5.5`).
- `lib/select.mjs` — `decide(text, {previous, clientModel, contextTokens, downgradeLimit, triage, triageFailed})`. With `triage` the score/level come from Haiku (signal `triage`) and its `trivial` may route to haiku; without it the rules apply as below.
  - Model by level (`LEVEL_MODEL`): trivial/simple/moderate → sonnet, complex/expert → opus; only an explicitly easy trivial prompt → haiku (`EASY_LEVEL_MODEL`); a prompt with no evidence does not go cheap (a wrongly cheap model hurts more).
  - Effort by score, per model (`effortFor`, `HIGH_EFFORT_THRESHOLD`): the model's default effort has a wide band (user's choice): haiku always the default, sonnet > 30 and opus > 75 one step above it, no low. The default and the step above come from the same model catalog cache (`effortsFromCatalog` in `lib/catalog.mjs`: the option badged "Recommended", today medium → high; `decide` gets them as `efforts`), falling back to medium/high when the catalog is unreadable. The user's `effortLevel` in `settings.json` is not used.
  - A short prompt (< 25 chars) with no signal ("go on") keeps the previous decision (`short-followup`).
  - Hysteresis: above the limit of estimated conversation tokens the model is not downgraded (`cache-hysteresis`); on the first decision the baseline is the client's model. Effort is computed after hysteresis, for the model that will run.
- `lib/display.mjs` — `label(d)`: the mode label right of the prompt (`⚡ Opus 5.5 · medium · complex 49`); `statusNotice(enabled)`; `autoCommand(args, enabled)`; `logSummary(records)`: the `/auto-log` text.
- `hooks/register.ts` (+ `hooks/hooks.json`, `.claude-plugin/plugin.json`):
  - `turn.start` gives the user's prompt text; on a turn without a typed prompt (a background agent's notification, a continuation) the text is empty and the previous decision stands. The decision comes from `decide`, the context estimate from `$.session.messages()`.
  - `turn.step` runs on every model request: with an `agentId` (subagent) it does nothing; when turned off with `/auto off` it does nothing (logged as `skipped: "off"`); otherwise, whatever the session model is, `next({ ...e, model, effort })`. It used to route only sonnet sessions with `/model` as the escape hatch; the user wanted it always on (2026-10-11), so the escape hatch became `/auto` (no argument toggles, `on`, `off`).
  - Effort: an incoming `e.effort` of `xhigh`/`max` is sent as is (`effortToSend` in `lib/select.mjs`), because Claude Code uses xhigh for an `ultrathink` turn since v2.1.311 (issue #4); the mod's own choice never goes that high. Side effect: a user who pins `effortLevel: xhigh` in settings also bypasses the mod's effort. Verified 2026-10-31 on v2.1.316 (plugin 0.1.5): an interactive `ultrathink` prompt was logged by `/auto-log` as `xhigh` (log times are UTC); the outgoing body was not checked with the spike observer. Since 0.1.6 such a step's record carries `chosenEffort` (the mod's own pick) and `/auto-log` marks it `session effort (mod: …)` and counts it (`Session effort kept`). The mode label next to the prompt shows the effort actually sent, too. The same keyword works in VS Code since v2.1.316; `CLAUDE_CODE_DISABLE_ULTRATHINK` turns it off.
  - Fallback: if the rewritten request yields no chunk, `usage` and `stopReason` are null and `next.signal` is not aborted (the user did not press Esc), the request is sent once more on the session's own model and that prompt goes passive (`reason: "rejected"`). `next()` re-runs what is beneath on every call. The v2.1.318 headless fixes (an API-errored or stopped response is no longer reported as success) did not change `TurnStepResult`: per the 2.1.318 types `usage`/`stopReason` are still null when no response arrived, so the condition holds.
  - Display: a `ui.render` hook on `SessionMode` adds text to the dim mode labels right of the prompt (`modes`); on change, `$.ui.invalidate('ui.render')`. Two layers: a lasting label (`label()`: the last decision; empty while off and before the first prompt) and a notice shown in its place for `NOTICE_MS` (4 s) (`statusNotice()`); the notice appears at `session.start` (startup and `/reload-plugins`) and after `/auto`, and is removed with `$.clock.after` (a timer that outlives the hook; `$.clock.sleep` would eat the hook's budget). User's choice (2026-10-11): "auto off" also disappears after 4 s, it is not a lasting label. `$.ui.status` is deliberately not used: Claude Code prefixes it with `⚠<plugin name>:` (only `$.ui.status(undefined)` at `session.start`, to clear one an older version left). The real model comes from the response's `usage.model`. Claude Code also prefixes command output with the plugin name, so `autoCommand` messages do not start with it. Validator rule: `$` may only be passed to functions declared at the top level of the file (not to a const function inside `register`), hence `show`, `notify` and the label state (`lasting`, `notice`) at module level.
  - Desktop (v0.1.7, surface check fixed in v0.1.8, emoji dropped in v0.1.9): the Claude desktop app runs the mod too (its bundled Claude Code, e.g. 2.1.317, loads the user-scope plugins; `turn.step` and `/auto-log` verified there on 2026-11-09 by matching desktop transcripts to the `decisions` log) but does not draw `SessionMode`. So when the render event's `e.surface` is `'desktop'` (v0.1.7 keyed on `session.start`'s surface, which the desktop's SDK-style process apparently does not report, and showed nothing), a second `ui.render` hook on `AbovePrompt` (raised on terminal and desktop) draws the same label/notice as a dim line above whatever band is beneath it (token-weather's); the terminal keeps `SessionMode` only. Verified on a real desktop session 2026-11-09 (v0.1.8: the line shows above token-weather's band without a clash). The ⚡ prefix is stripped there because its glyph width misaligned the text with token-weather's ☀ icon.
  - Log: every main-conversation model request goes to `$.store` under the `decisions` key (last 2000; step, model, effort, level, score, reason, responseModel, cacheWrite/cacheRead, fallback, skipped); `/auto-log` summarizes it. No file log: `$.fs.write` writes whole files only. (The Turkish-era key `kararlar` is no longer read.)
- Mod API types: the plugin-authoring skill's `types/claude-code.d.ts` (`'turn.step'`, `TurnStepInput`, `TurnStepResult`, `HookStream`, `RenderComponent`). The engine writes `.claude-plugin/types/` and a root `tsconfig.json` when it loads the mod (both gitignored). The test kit (`claude plugin test`) cannot raise `turn.step`, so the decision logic is tested with Node in `test/*.test.mjs`; `test/notice.test.ts` uses the kit for the display: `$.session.start(...)`, `$.ui.mount({ component: 'SessionMode' })` and `mock.clock(on).advance(ms)`. Hooks a test registers sit beneath the plugin and stand in for the engine: a `$` call the plugin makes (`command.register`, `ui.status`) must be answered with `{ value }`, and an engine component (`ui.render` on `SessionMode`) needs a test hook that draws it. A plugin name cannot start with `claude-` (reserved for Anthropic). The mod API is "EARLY ACCESS" and may change between Claude Code versions.

## Verified (2026-10-10/11 on v2.1.296, re-checked 2026-10-17 on v2.1.302; Claude Pro/OAuth)

- The installed mod with plain `claude -p`: an easy prompt → outgoing request `claude-haiku-5-5`/`medium`, answered by Haiku, `modelUsage` `claude-haiku-5-5`; score 37 → `claude-sonnet-5-5`/`high` (with the spike observer). A session started with `--model opus` also routes (easy prompt → Haiku). Interactive: haiku → sonnet switch seen; `/auto-log` showed real records; the `SessionMode` label shows right of the prompt with no prefix.
- **Tool search and base URL:** when `ANTHROPIC_BASE_URL` points to a non-first-party host, Claude Code turns MCP tool search off and loads every MCP tool upfront ([mcp](https://code.claude.com/docs/en/mcp), "Configure tool search"). On the old proxy path the base context was ~280k (189k MCP tools); with the mod ~68k. This was true up to v2.1.303; v2.1.304 turned tool search on by default behind a custom `ANTHROPIC_BASE_URL` (a gateway 400/422 is retried without it).
- Cache: within one model the read ratio is 82–92%; changing effort does not break the cache. The first switch to each model rewrites the whole context; a cache write costs ~12.5× a read. The user chose to keep the switching rules as they are (2026-10-11).
- Multi-turn model switches (haiku → opus, thinking blocks included) were not rejected by the API (interactive, during the proxy era).

- Re-checked on Claude Code v2.1.302 (2026-10-17): `claude plugin validate .` passes (its only warning says a root `CLAUDE.md` is not loaded as plugin context, harmless), logic and kit tests pass, and a real `claude -p "mimari nedir?"` was triaged by Haiku (`trivial (3)`, no `rules-fallback`) and answered by `claude-haiku-5-5`. The 2.1.297–302 release notes have nothing that breaks the mod; no change was needed for the upgrade itself. The `<task>`-tag triage fix (v0.1.4) was checked on two real prompts with no `rules-fallback`; whether `unparseable` still shows up needs a few days of `/auto-log`.
- Re-checked on Claude Code v2.1.308 (2026-10-22): same result (validate passes with the same warning, 36 logic tests and the kit test pass, a real `claude -p "mimari nedir?"` → Haiku triage `trivial (2)`, no `rules-fallback`, answered by `claude-haiku-5-5`). The 2.1.303–308 release notes have nothing that breaks the mod. Relevant but harmless: tool search on by default behind a custom base URL (2.1.304), `opus[1m]` alias fix (2.1.307; `learnModel` still ignores suffixed ids on purpose), mod API additions we do not use (`tool.check` `decider`/`isReadOnly`, per-layer `settings.read`).

## Risks and unverified

- The fallback path has not been triggered by a real API rejection.
- Haiku triage over raw `/v1/messages` depends on Claude Code internals (the identity line, the credential handle); if a release changes them every prompt quietly takes `rules-fallback`, and `triageNote` shows why. Screenshot triage verified once end to end (`claude -p --plugin-dir .` with a stream-json image prompt → `simple (8) · 1 image`, reason `score`).
- Haiku triage: verified once with `claude -p` ("mimari nedir?" → Haiku 2, trivial); the rating scale in `TRIAGE_SYSTEM` is not calibrated on real use, and the rules-fallback path fired in real use (2026-10-11, three Opus decisions at score 77; cause unknown, `triageNote` now records it); `unparseable` was seen once (2026-10-13) and addressed in v0.1.4 with the task tags, so watch `/auto-log`.
- The scorer is rule-based and not yet calibrated on real use. "tasarım" (design) also counts as heavy for UI work.

## History and rejected approaches (short)

- **Proxy (deleted 2026-10-11):** a local router behind `ANTHROPIC_BASE_URL` rewrote `model` and `output_config.effort` in the request body; it worked with the subscription OAuth headers forwarded as-is. Problems: it turned tool search off and blew up the context 4×, Claude Code did not know the real model, and it was a terms-of-service gray area. The code is in git history (`5abccb7` and earlier). The proxy-era decision/cache log is `tools/router-proxy-era.log` (not in git).
- **Hook + skill:** a `UserPromptSubmit` hook cannot change model/effort. A skill's frontmatter `model` override does not change the main model ([model-config](https://code.claude.com/docs/en/model-config): "Claude Code ignores the override …"), though the UI still shows a `claude-opus-5-5` label (misleading). Prototype in commit `9075d5e`.
- **MCP:** gives the model tools; it cannot change the request's model.
- **Subagent delegation** (`gorev-kolay/orta/zor` + the global `CLAUDE.md` "Model Yönlendirmesi" rule): the main model does not change, and it was rarely used; removed 2026-10-11, agent files in `~/.claude/agents-yedek-20261011-132617/`.
- **OmniRoute / CLIProxyAPI:** pick across providers by cost/quota/health, not prompt difficulty; they hand the subscription token to a third party. Only OmniRoute's difficulty-score idea was taken. Old CPA env leftovers in the user's `settings.json` were removed on 2026-10-11 (backup `~/.claude/settings.json.yedek-20261011-171206`).
